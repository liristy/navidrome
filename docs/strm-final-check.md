# STRM 最终检查记录（2026-09-06）

交付版本：`0.63.2-liristy (afb3a2f8)`。
镜像：`navidrome-strm-nfo:0.63.2-liristy`，平台 `linux/amd64`。
源码为上游提交 `afb3a2f8` 加工作区 STRM/NFO 补丁；不是原封不动的官方 0.63.2 release。

## 本轮修复

- 新版转码决策为 STRM 正常签发令牌，播放时先校验；不再一律丢弃转码参数。
- Redia 跳转限于显式启用兼容、本地白名单目标、GET/HEAD 原码播放。真实转码、HTTP 指针及 POST 保留原生播放流程。
- 跳转使用同域绝对路径，保留 BaseURL 前缀，避免简单字符串替换改错路径以及部分客户端下载器不支持 `./stream` 的问题。
- HTTP STRM 的 POST 播放以 GET 读取上游，避免发送不必要的上游 POST。
- 新版播放接口不再把正常 HEAD、304、416 的零字节响应当成错误追加输出。
- 未知目标音频大小不再把 STRM 文本长度写进新 NFO；已有用户 NFO 不会被覆盖。
- 版本号简化为 `0.63.2-liristy`，关于页链接指向官方基础版本，保留提交号用于追踪。

## 验证结果

- Linux 非 root 环境下 20 个后端测试包通过，覆盖 STRM、NFO、配置、模型、存储、播放、FFmpeg、封面、扫描、持久化、数据库迁移、Subsonic；部分上游测试按平台等条件跳过。
- 关于页版本链接与前端转码决策服务测试通过。
- 成品镜像断网自检通过：启动、UI、中文/韩文路径、真实 FLAC 标签/歌词/技术参数读取、安全 NFO 生成、数据库入库和原生 API 兼容字段。
- 真实客户端能力配置可获得原码播放令牌；校验后返回 307。客户端经过该跳转续传，收到 206 和正确的 Content-Range，续传文件与源音频逐字节一致。
- 无效令牌返回 410；要求转码的客户端通过新版接口取得实际 MP3，不会错误跳转到原码音频。传统接口原码/MP3 也通过。
- 从用户原始备份重新复制独立数据库：升级前后 integrity_check 均为 `ok`；986 首曲目、1 个用户、21 个歌单数量不变。旧库缺失迁移自动补齐，升级至 `20260905132000`，新版本成功启动。原始备份未修改。
- 导出的 tar 标签、镜像 ID 与运行测试的镜像一致，SHA256 校验通过。
